### 0.2 電気系統の指摘

| # | 指摘 | 対応方針 |
|---|------|----------|
| B1 | Raspberry Pi（Linux）はリアルタイム OS ではない。数百 Hz〜kHz の姿勢制御ループを担うフライトコントローラ（FC）には不適。業界の定石は「マイコン FC ＋ Linux コンパニオンコンピュータ」の二層構成。 | 内側ループ（姿勢・角速度制御）はマイコン（ESP32-S3 / STM32 など）が担う。Raspberry Pi は経路計画・画像処理などのコンパニオン（任意）とする。 |
| B2 | ブラシレスモータ用 ESC をディスクリート部品で自作するのは、三相インバータ・ゲートドライバ・センサレス転流が必要で難度が高く、発火リスクもある。 | 機体を2クラスに分ける。**クラスA**（既定）は100g未満のマイクロ機で、ブラシ付きコアレスモータを MOSFET で駆動する。全回路をディスクリート部品と汎用モジュールで構成でき、学習と安全性に優れる。**クラスB** は250mm級のブラシレス機で、ESC は市販品（オープンソースファームウェア AM32 対応品）を採用する。 |
| B3 | 「自律飛行（目標地点・経路）」には自己位置推定が必須。屋内では GPS が使えない。 | クラスAはオプティカルフロー（PMW3901）とToF距離センサ（VL53L1X）で位置推定する（Crazyflie Flow deck と同じ定石）。クラスBは GNSS を使う。シミュレータにもこれらのセンサモデルを入れる。 |
| B4 | MPU-6050 など定番 IMU は製造終了（EOL）品が多く、「替えがきく」方針に反する。 | 現行品（ICM-42688-P、BMI270、LSM6DSO）を採用し、代替候補を必ず併記する。 |
| B5 | 1S LiPo はモータ負荷時に電圧が大きく下がる（サグ）。3.3V レギュレータのドロップアウトでマイコンがブラウンアウトする事故が典型。 | 低ドロップアウト LDO＋バルクコンデンサを使い、電源系を分離する。電圧降下を回路計算とシミュレーション（電池内部抵抗モデル）の両方で扱う。 |

## 1. 目的

飛行体（固定ピッチ・非偏向の多ロータ機）の、シミュレーション・電気設計・基板設計・機体設計を一貫して支援するツールを作る。設計データを単一モデルで共有し、シミュレーション結果と実機設計が整合することを目指す。

## 2. 段階別の機能要件とゴール（合格基準）

各段階はゴール判定をスクリプトで自動化する。結果とスクリーンショットを HTML レポート（`reports/stageN.html`）に出力する。

### 段階1: 飛行空間・シミュレーション

**機能**
- F1-1 Three.js による 3D 空間。重力・空気密度・風（平均風ベクトル＋突風）を設定できる。
- F1-2 地面と障害物（直方体・円柱）、開始点、目標点、経由点をコース定義（JSON）で設定できる。
- F1-3 6自由度剛体動力学。モータ一次遅れ、推力 ∝ ω²、反トルク、空気抵抗、地面効果、電池電圧降下を含む。
- F1-4 センサモデル（IMU ノイズ・バイアス、気圧計、位置センサ）と状態推定。
- F1-5 カスケード制御（位置→速度→姿勢→角速度）と制御配分（任意 N ロータ）。
- F1-6 自律飛行: 障害物を避ける経路計画（3D A*）と経路追従。
- F1-7 手動飛行: キーボード操作。
- F1-8 飛行軌跡の表示、テレメトリ表示、衝突検出。

**ゴール**
| ID | シナリオ | 合格基準 |
|---|---|---|
| G1-1 | 高度1mホバリング10秒（センサノイズあり） | 定常高度誤差 RMS < 0.05 m |
| G1-2 | 正方形コース経由点飛行 | 全経由点を 0.15 m 以内で通過 |
| G1-3 | 障害物コース自律飛行 | 衝突なし、目標到達誤差 < 0.2 m |
| G1-4 | 平均風 3 m/s＋突風 1 m/s 中のホバリング | 水平位置誤差の最大値 < 0.5 m |
| G1-5 | 電池電圧降下 | 低電圧時に自動着陸し、墜落しない |

### 段階2: 推進系サイジングと電気系統設計

**機能**
- F2-1 目標全備重量・推力重量比から、プロペラ・モータ・電池の必要スペックを算出する（運動量理論）。
- F2-2 飛行時間・ホバリング電流・最大電流を推定する。
- F2-3 回路（電源、マイコン、センサ、モータ駆動、電池監視）を自動生成し、各部品の理想スペックを計算する（MOSFET 電流余裕、ゲート抵抗、LDO 電流・ドロップアウト、分圧比など）。
- F2-4 回路図（SVG）、ネットリスト、BOM を出力する。全部品に代替品を1つ以上併記する。

**ゴール**
| ID | 合格基準 |
|---|---|
| G2-1 | 推力重量比 ≥ 2.0、ホバリングスロットル ≤ 60 % |
| G2-2 | 推定ホバリング飛行時間 ≥ 5 分 |
| G2-3 | 電気的検証（電流余裕2倍以上、ADC 入力範囲内、LDO 余裕）がすべて合格 |
| G2-4 | ネットリストに未接続ピン（意図的な NC を除く）がない |

### 段階3: 部品選定・3Dモデル・ブレッドボード・基板設計

**機能**
- F3-1 BOM の各部品を部品カタログ（型番・寸法・重量・仕様・購入先検索 URL）に対応付ける。
- F3-2 パッケージ規格ごとのパラメトリック3Dモデル生成と、アーカイブ（GLB/STL）出力を行う。
- F3-3 ブレッドボード配置図（SVG）を作る。
- F3-4 PCB の自動配置、2層自動配線、GND ベタ、スティッチングビア、発熱部品下のサーマルビア、DRC を行う。
- F3-5 Gerber（RS-274X）とドリル（Excellon）を出力し、基板製造サービスに入稿できる ZIP にまとめる。
- F3-6 実装済み基板の3D表示を行う。

**ゴール**
| ID | 合格基準 |
|---|---|
| G3-1 | BOM 全部品がカタログに対応し、寸法・重量を持つ |
| G3-2 | 使用する全パッケージの3Dモデルが生成される |
| G3-3 | PCB の全ネットが配線済み（未配線 0） |
| G3-4 | DRC（クリアランス・線幅・穴径）違反 0 |
| G3-5 | Gerber 一式とドリルファイルが出力される |

### 段階4: 機体総合設計

**機能**
- F4-1 プロペラ径とクリアランスから腕長を決めるパラメトリックフレームを生成する。
- F4-2 部品配置（基板、電池、モータ、センサ）を行い、質量特性（重心、慣性テンソル）を計算する。
- F4-3 重心と推力中心が一致するよう電池位置を自動調整する。
- F4-4 3Dプリント用 STL を出力する。
- F4-5 電子部品を搭載した機体の3Dを UI で確認できる。

**ゴール**
| ID | 合格基準 |
|---|---|
| G4-1 | 重心と推力中心の水平ずれ < 2 mm |
| G4-2 | プロペラ間・プロペラとフレームの隙間 ≥ 5 mm |
| G4-3 | 出力 STL が閉じた多様体（watertight） |
| G4-4 | 全備重量 < 100 g（クラスA） |

### 段階5: 統合（Sim-to-Real ループ）

**機能**
- F5-1 段階2〜4の設計値（質量、慣性、腕長、推力係数、電池）からシミュレーション用パラメータを自動導出する。
- F5-2 段階1のシナリオを実設計値で再実行し、参照機との比較を行う。
- F5-3 完成機体（フレーム＋基板＋部品＋モータ＋プロペラ＋電池）の3Dを UI 上で表示し、そのまま飛行シミュレーションできる。

**ゴール**
| ID | 合格基準 |
|---|---|
| G5-1 | 実設計値で G1-1〜G1-5 に合格 |
| G5-2 | 完成機体の3Dが UI に表示される（スクリーンショットで確認） |

## 3. 非機能要件

- TypeScript（`any`/`unknown` 禁止、`class` 原則禁止）で実装する。
- コア計算（物理・制御・設計）はブラウザ非依存とし、Node でもテストとバッチ実行ができる。
- 物理は固定刻み 1 kHz、制御は 500 Hz、描画は 60 fps で分離する。
- 設定値はハードコードせず、プリセット・設定ファイルに外出しする。
- 各段階の検証は `npm run stageN` で再現できる。

## 4. スコープ外（今回実施しない）

- 実機ファームウェアの実装（要件と構成案のみ示す）
- 販売サイトのリアルタイム価格取得（API キーが必要なため拡張ポイントのみ用意）
- 構造解析（FEM）と振動解析

## 改良版 B（2026-09-27 追加）

元の設計（以下「版 A」：既製フロー＋ToF モジュールをケーブル接続）は変更せずに残し、改良版 B を並行して作る。

### 背景（版 A の課題）
- フロー＋ToF は既製ブレイクアウト頼みで、回路・基板・3D を設計していない（plan.txt の「ディスクリート中心」方針から外れる）。
- メイン基板の J2 とプレート下のモジュールをつなぐケーブルの通り道がフレームにない。
- GNSS（屋外飛行）の接続手段がない。

### 機能要件
- FB-1 フロー（PMW3901 系）＋ToF（VL53L1X）を載せた**センサ子基板**を回路・基板・Gerber・3D まで自動生成する。1.8 V 系電源（フローセンサのコア電圧）を子基板上で作る。
- FB-2 子基板はメイン基板と同じ 8 ピン配列の JST-SH で接続し、フレーム機首の M2 穴 2 個で固定する。部品面を床に向けて取り付ける。
- FB-3 フレームにケーブル通し穴を追加する。
- FB-4 版 B のメイン基板に GNSS 用 JST-SH 6 ピン（3V3・GND・UART TX/RX・I²C）を追加する（モジュール本体は未搭載）。
- FB-5 GNSS の誤差モデル（ゆっくり変動する位置誤差）を追加し、GNSS モジュール装着時の屋外飛行をシミュレーションで検証する。
- FB-6 版 A と版 B の重量・重心・飛行性能を比較する HTML レポートを出力する。UI でも版 B の完成機体を表示・飛行できる。

### ゴール
| ID | 合格基準 |
|---|---|
| GB-1 | 子基板: 全ネット配線・DRC 違反 0・Gerber 構文エラー 0 |
| GB-2 | 版 B メイン基板: 全ネット配線・DRC 違反 0（GNSS コネクタ込み） |
| GB-3 | 版 B 機体: 重心ずれ < 2 mm、STL が閉じた多様体、全備重量 < 100 g |
| GB-4 | 版 B で G1-1〜G1-5 に合格 |
| GB-5 | GNSS 装着の屋外シナリオ（経由点飛行・耐風ホバリング）に合格 |
